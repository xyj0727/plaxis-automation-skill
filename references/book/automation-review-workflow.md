# 从教程操作转成可审查脚本

本文件把教程的对象、阶段和结果检查方法组织为自动化工作流。具体知识和例题参数见同目录主题文件；它不规定缺少依据的工程数值。

## 先建立完整工况表

用 Markdown 表记录全模型，不只列相对某模板的改动。每个输入至少包含：物理含义、值、单位、来源页/试验/用户说明、是否固定、实际回读值及状态。状态采用 `confirmed`、`source-defined-but-not-confirmed`、`unset-or-not-read-back`。

|模型部分|需要明确和回读的内容|
|---|---|
|几何与概化|全/半/四分之一模型，坐标和高程基准，范围，钻孔/层面，结构实体/板/梁/埋入构件的选择，界面延伸与几何分区|
|材料|本构模型、排水类型、重度、刚度与应力依赖、强度/剪胀、初始应力历史、渗透/持水参数；结构截面、厚度、局部轴和重度|
|水与初始应力|地下水位或水头，流边界、封闭/开放面，初始孔压与超孔压，K0/重力/场应力的适用条件，OCR/POP|
|边界与加载|位移/力方向和分量、约束、对称面、水动力边界、载荷分布、荷载位置和高度、时间乘子及单位|
|接触与连接|正/负界面、材料确定方式、Rinter或直接参数、水力透过性、机械/水力激活、刚性/铰接/弹簧连接|
|网格|全局/局部尺寸策略、曲线面离散、细化对象、网格统计与敏感区质量、拟观察点位置|
|阶段|父阶段、计算类型、每步开挖/激活/材料/荷载/水力变化、持续时间、位移清零、状态继承和安全分析分支|
|求解与存储|默认/手动控制的实际状态、容限、步长、迭代、弧长、更新网格、核心数、保存步预算和失败停止条件|
|结果|工程/阶段/步、节点或应力点、对象和材料子域、坐标系、位移/力/孔压口径、曲线横纵轴、平衡与收敛检查|

书中例题表格只能作为 `source-defined-but-not-confirmed` 的来源。对新的研究工程，先报告缺失参数及其影响，请用户提供或确认，不用批量试算来替用户选物理参数。

## 写完整脚本后再构建

脚本的流程应能独立重放：连接并确认工程身份 → 几何与材料 → 结构/接触/水 → 网格 → 完整阶段树 → 保存及逐项回读 → 获得授权的计算 → 脚本打开 Output 并提取结果。按任务需要可分模块，但不能靠未记录的手动点击补齐关键状态。

把 GUI 教程步骤转换为脚本时，先区分三种作用域：

- 几何/材料定义：对象存在和材料数据库数据；修改共享材料可能影响多个对象及阶段。
- 分阶段状态：特定阶段的激活、荷载、水力条件及计算参数；不能仅检查当前可见阶段。
- 结果状态：已计算且实际存储的阶段与步；不能用 Input 的目标状态代替 Output 的计算到达状态。

几何运算后对象可能被分割或重命名。用几何位置、面积/体积、材料与父子关系核验目标，不能把书中的对象编号硬编码为所有新模型的编号。

## 小模型验证的作用

全部工况参数确认后，选易报错工况或与正式工况参数明确关联的等效小模型。先完成建模、回读、正常收敛及关键结果提取，再展开所有正式工况脚本。小模型用于验证实现与流程，不用于凭空确定界面或本构参数；缩小模型时须说明哪些机制/边界/荷载关系保持等效。

对于本次纯知识整理，没有自动启动示例求解。日后用户要求复现书中案例时，先引用该案例模块中的完整参数与阶段，并列出书中未说明而当前版本需要补齐的项。

## 构建和计算后的核查

1. 检查原始设计与生成对象的几何数量、位置、法向、共享边及体积关系；防止实体结构和土体重叠造成重量或刚度重复。
2. 材料回读既检查数值，也检查决定数值是否生效的模型/排水/确定方式；单位变更后几何、荷载、渗透和时间必须分别检查。
3. 遍历阶段树核对父阶段、实际激活集合、荷载和孔压继承；不要让安全折减后的状态成为正常施工阶段的起点。
4. 计算后核对每阶段原生状态、日志和达到的目标；遇到失败记录最后可靠状态，不把失败阶段补成零值或假定成功。
5. Output 用真实对象、坐标和材料子域选择数据；保存原始数据、单位、符号、数据位置及实际存储步信息。节点外推值与应力点值不得无说明混用。
6. 用位移形态、超孔压演化、反力/内力与平衡、塑性点和网格敏感性共同检查解释；云图的变形放大倍数和色标范围不能成为定量结论。

## 交付时能回答的问题

哪些输入是用户确认的，哪些只来自书中示例？实际执行了哪个脚本、哪个工程及哪些阶段？是否正常收敛？结果来自哪个保存步、哪个物理对象和坐标系？哪些新版本映射仍未运行验证？这五类答案应可以从工况表、原生工程和结果记录追溯。
